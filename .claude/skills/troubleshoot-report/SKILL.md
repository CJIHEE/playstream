# /troubleshoot-report <시나리오 이름>

## 원칙
- **모든 수치는 `loadtest/results/` 아래 실측 파일 경로를 근거로 붙인다.** 근거가 없으면 `[측정 필요]`로 표시하고 추정하지 않는다.
- Grafana 스크린샷은 `loadtest/results/<시나리오>/` 아래 경로로 참조한다.

## 문서 템플릿: `docs/troubleshooting/<NN>-<시나리오>.md`
```
# <제목: 증상 → 원인 → 조치가 드러나게>

## 1. 상황
- 환경: 인스턴스 사양, 브로커·파티션 수, 부하 조건
- 증상: 무엇이 관찰되었나 (지표 + 근거 파일)

## 2. 가설과 검증
| 가설 | 확인 방법 | 결과 |

## 3. 원인

## 4. 조치
- 변경 내용 (PR 링크), 대안과 선택 이유

## 5. 결과 (before → after)
| 지표 | Before | After | 근거 파일 |

## 6. 배운 점 / 한계

## 7. 이력서 한 줄
- (수치 포함, 근거 파일이 있는 것만)

## 8. 예상 면접 꼬리질문
```

## 진행
1. `loadtest/results/<시나리오>/` 파일을 읽어 표를 채운다.
2. 비어 있는 칸은 사용자에게 질문해서 채운다. 임의로 채우지 않는다.
3. 작성한 내용을 보여주고 승인받은 뒤 저장한다.
